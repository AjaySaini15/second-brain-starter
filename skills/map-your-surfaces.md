# SKILL — Map your surfaces (build your eyes, part 1 of 2)
<!-- A guided inventory of where your work signal lives, ending in a ranked
"eyes roadmap" — which input stream to connect first. Run once at Walk stage,
revisit quarterly. Dictated answers, as always. -->

You are helping me inventory every surface where my work signal lives, so we can decide which eyes to build first.

## Steps
1. **Sweep** — walk me through these categories and ask what I actually use (dictated answers fine):
   meetings (online + physical) · email · calendar · chat (Slack/Teams/WhatsApp) · documents & sheets · CRM/ticketing/ERP · dashboards & reports · voice notes · my own screen · anything domain-specific.
2. **For each surface I name, capture four things:**
   - SIGNAL: what decisions/facts/commitments live there (high/medium/low density)
   - ACCESS: easiest export path — native transcript? file export? API? forward-to-email? copy-paste? (rank by friction)
   - VOLUME: items per week
   - SENSITIVITY: personal / work-ok / work-restricted (company policy!)
3. **Rank** — score each surface: signal density × ease of access, sensitivity as a gate not a score. High-signal + low-friction + low-sensitivity wins.
4. **Output the roadmap:**
```
MY EYES ROADMAP — <date>
NOW (this week, zero code):  <surface> via <manual path — e.g., paste Meet transcripts>
NEXT (this month):           <surface> via <export/forward routine>
BRIDGE (this quarter):       <surface> via <thin script — see build-a-bridge skill>
NOT YET / NOT EVER:          <surfaces gated by sensitivity or policy — say why>
5. Save to the brain folder as `eyes-roadmap.md` and add one MEMORY.md line.
```

## Rules
- Meetings almost always rank first — highest decision density, native transcripts everywhere. Challenge me if I rank them low.
- One surface at a time. An eyes roadmap with five parallel builds is a graveyard.
- **Company policy is a hard gate:** if a work surface is restricted, it goes to NOT YET — never "we'll be careful."
