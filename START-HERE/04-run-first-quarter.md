# Run — the first quarter

**Goal:** the AI stops waiting for you. It acts on schedule, connects to your real surfaces, and you become the approval gate instead of the operator. This is where code enters — or at least the terminal.

## What changes at this level
- **Claude Code / CLI** (same thing, two clothes): the AI can read and write your files directly, run scripts, and build its own tools. When something is blocked — an API, an export, a connection — it writes the bridge itself. A brain with hands routes around handicaps.
- **Schedules:** your daily brief generates before you wake. Your weekly review drafts itself Friday evening. You review; you don't produce.
- **Human gates:** every consequential output (an email, a task list for your team) lands in a staging file you approve — maker-checker, like any good org. Automation without gates is how you lose trust in your own system.

## The order to build in
1. Automate the skill you run most (for me: meeting processing). Schedule it.
2. Add a staging/review step to it. Get used to approving instead of writing.
3. Build one bridge to a surface you use daily (calendar, mail, sheets).
4. Only then expand. One reliable automation beats five flaky ones.

## Two warnings from my own scars
- **Don't over-build.** Past a point, more rules make the system brittle and fussy. I've had to learn when to stop tuning. If you're adding corrections faster than you're using outputs, stop and simplify.
- **Watch your tokens.** Heavy off-the-shelf connectors load their whole toolset into every call. Thin scripts you own are cheaper and clearer.
